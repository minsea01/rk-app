# 基于 RK3588 智能终端的行人检测模块项目说明书

## 1. 项目概述

本项目面向 RK3588 边缘智能终端，实现一套工业相机实时采集、NPU 推理、检测结果上传和浏览器实时演示的行人检测系统。系统以 RK3588 板端为核心，使用 GigE 工业相机作为图像输入，采用 YOLO 系列轻量化检测模型，经 ONNX 导出、RKNN 转换和 INT8 量化后部署到 RK3588 NPU 上运行。

项目当前主线为：

- 硬件平台：RK3588 aarch64，Ubuntu 20.04.6 LTS
- 相机：Hikrobot / Hikvision MV-CA020-20GC GigE Vision 工业相机
- 输入分辨率：1920x1200，30 FPS，GRAY8
- 主模型：`best_person_aug_416_norm_int8.rknn`
- 主任务：行人检测，类别为 `person`
- 扩展验证：`yolo11n_coco80_416_int8.rknn`，支持 COCO80 类，用于满足任务书“检测/识别物体种类大于 10 种”的扩展口径
- 现场演示：浏览器实时查看检测结果，地址 `http://localhost:8080`

## 2. 产品说明

### 2.1 产品定位

本产品是一套部署在 RK3588 边缘智能终端上的实时行人检测模块，面向工业现场、园区安防、智能交通和边缘 AI 演示场景。系统在本地完成图像采集、模型推理和结果输出，不依赖云端 GPU 服务器，具有低功耗、低延迟、部署简单和现场演示直观的特点。

产品形态包括：

- 一套可运行的 RK3588 板端检测软件包。
- 一套 GigE 工业相机实时采集和检测配置。
- 一套浏览器实时查看页面。
- 一套模型、配置、部署脚本和验收报告。
- 一套 COCO80 多类别扩展验证配置。

### 2.2 产品功能

| 功能 | 说明 |
|---|---|
| 工业相机接入 | 通过 GigE Vision 接入 MV-CA020-20GC 工业相机，采集 1920x1200 实时图像 |
| 行人检测 | 使用 INT8 RKNN 行人检测模型，在 RK3588 NPU 上完成实时推理 |
| 结果上传 | 通过独立上传网口将检测框、置信度、类别和图像发送到 PC/WSL |
| Web 实时预览 | 浏览器显示实时画面、检测框、结果帧率、图像帧率和接收流量 |
| 画面辅助调试 | 支持 `Fit / 1:1 / 2x` 显示，用于现场调焦和观察远处细节 |
| 图像质量控制 | 支持调整 JPEG 质量、图像上传间隔和图像 ROI 区域 |
| 多类别扩展 | 提供 COCO80 RKNN 配置，用于验证超过 10 类的检测能力 |
| 自动部署 | 支持一键部署到 `/opt/rk_app_current`，降低现场配置复杂度 |

### 2.3 产品特点

1. **边缘本地推理**
   - 图像不需要上传云端，检测在 RK3588 本地完成。
   - 适合网络受限、数据不便外传或需要低延迟响应的场景。

2. **双网口分离**
   - `eth1` 专用于工业相机采集。
   - `eth0` 专用于 SSH、检测结果和 Web 图像上传。
   - 采集链路和上传链路互不混用，便于现场排障。

3. **轻量化模型部署**
   - 使用 416 输入尺寸和 INT8 RKNN 模型。
   - 避免 640 模型在 RK3588/RKNN 上触发 Transpose CPU fallback。
   - NPU benchmark 达到 `52.93 FPS`，mean latency `18.89 ms`。

4. **现场演示友好**
   - PC 端只需浏览器即可查看实时效果。
   - 页面直接显示 `result fps`、`image fps`、`rx MiB` 和运行状态。
   - 当前实测图像和检测结果同步约 `19 FPS`。

5. **可扩展**
   - 主系统用于行人检测。
   - 通过替换模型、类别文件和配置，可扩展到 COCO80 或自定义目标检测任务。

### 2.4 典型应用场景

| 场景 | 使用方式 |
|---|---|
| 工业通道行人检测 | 相机固定安装在通道、门口或设备区域，检测人员进入 |
| 园区/厂区安全监控 | 本地识别人员目标，并上传结构化检测结果 |
| 智能交通边缘节点 | 对行人、车辆等目标进行边缘侧识别 |
| 毕业设计现场演示 | 浏览器实时展示工业相机画面和检测结果 |
| RK3588 AI 部署验证 | 验证 ONNX 到 RKNN、INT8 量化和 NPU 多核推理流程 |

### 2.5 产品使用边界

1. 工业相机镜头为手动调焦，远处清晰度取决于实际焦点位置。
2. 当前主模型为行人检测模型，类别为 `person`；多类别检测需切换到 COCO80 配置。
3. 实时 Web 图像上传会增加 CPU 编码和网络负载；正式性能验收建议关闭图像上传或降低上传频率。
4. 当前系统以固定相机实时检测为主，不包含云端管理平台、数据库存储和告警联动模块。

## 4. 系统组成

### 4.1 硬件组成

| 模块 | 说明 |
|---|---|
| RK3588 主板 | 四核 Cortex-A76 + 四核 Cortex-A55，内置 6 TOPS NPU |
| 工业相机 | Hikrobot MV-CA020-20GC，GigE Vision 接口 |

| 上位机 | Windows + WSL，本地浏览器查看实时检测画面 |

### 4.2 网络拓扑

当前实测拓扑如下：

| 网口 | 用途 | 地址 |
|---|---|---|
| RK3588 `eth1` | 工业相机采集网络 | `192.168.1.10/24` |
| 工业相机 | GigE Vision 图像源 | `192.168.1.12` |
| RK3588 `eth0` | SSH、检测结果上传 | `192.168.137.226/24` |
| PC/WSL 接收端 | TCP 结果接收、Web 展示 | `192.168.137.1:9000` |

数据流方向：

```text
GigE 工业相机
  -> RK3588 eth1
  -> GStreamer / GigeSource
  -> 预处理 / RKNN NPU 推理 / 后处理
  -> RK3588 eth0
  -> PC/WSL TCP receiver
  -> Browser Web viewer
```

## 5. 软件架构

项目采用 C++ 主链路实现，Python 脚本负责训练、模型转换、部署、验收和报告生成。

### 5.1 目录结构

| 路径 | 作用 |
|---|---|
| `src/capture/` | 视频、GigE、CSI、MPP 等输入源实现 |
| `src/preprocess/` | 图像格式转换、letterbox、ROI、增强处理 |
| `src/infer/rknn/` | RKNN 推理引擎与 RK3588 NPU 适配 |
| `src/post/` | NMS、类别映射、检测结果过滤 |
| `src/output/` | TCP JSON/JPEG 输出 |
| `src/pipeline/` | 检测流水线、配置加载、跟踪稳定 |
| `examples/detect_cli.cpp` | 板端主运行程序 |
| `config/detection/` | 运行配置文件 |
| `scripts/deploy/` | 板端部署和网络配置脚本 |
| `scripts/demo/` | 实时 Web 演示启动、状态、停止脚本 |
| `scripts/live_web_viewer.py` | PC/WSL 侧 TCP 接收和 Web 页面 |
| `artifacts/models/` | ONNX/RKNN 模型文件 |
| `artifacts/` | 验收报告、日志、实时截图和临时产物 |

### 5.2 核心流程

1. `GigeSource` 通过 GStreamer 从工业相机读取 GRAY8 图像。
2. `DetectionPipeline` 对图像进行 ROI、letterbox 和格式整理。
3. `RknnEngine` 调用 RKNN Runtime，在 RK3588 NPU 上执行 INT8 模型。
4. 后处理模块完成阈值过滤、NMS、类别名称映射。
5. `TcpOutput` 将检测框、置信度、类别、可选 JPEG 图像打包成 JSONL 发送到 PC。
6. `live_web_viewer.py` 接收 TCP 流，并提供 `/stream.mjpg`、`/api/latest`、`/latest.jpg` 等 Web 接口。

## 6. 模型与算法

### 6.1 主行人检测模型

当前主演示模型：

```text
artifacts/models/best_person_aug_416_norm_int8.rknn
artifacts/models/best_person_aug_416_norm_int8.rknn.json
```

模型特点：

- 输入尺寸：416x416
- 量化方式：INT8
- 检测类别：1 类，`person`
- sidecar 元数据：`head=raw`，`num_classes=1`
- 当前用途：实时行人检测主链路

选择 416 输入尺寸的原因：

- 640 模型在 RK3588/RKNN 上容易触发 Transpose CPU fallback。
- 416 输出规模更小，能够规避 RKNN NPU Transpose 元素限制。
- 实测 NPU benchmark 达到 `52.93 FPS`，mean latency `18.89 ms`。

### 6.2 COCO80 扩展模型

任务书要求“检测或识别物体种类大于 10 种”。项目主线是行人检测，因此多类别能力作为扩展验证提供：

```text
artifacts/models/yolo11n_coco80_416_int8.rknn
artifacts/models/yolo11n_coco80_416_int8.rknn.json
config/coco80_names.txt
config/detection/detect_coco80_rknn.yaml
```

该模型支持 COCO80 类，包括 person、bicycle、car、motorcycle、bus、truck、cat、dog 等，满足“>10 类”的任务书指标。

### 6.3 后处理策略

主行人检测配置：

```yaml
postprocess:
  conf_threshold: 0.40
  nms_threshold: 0.35
  max_detections: 300
```

配置说明：

- `conf_threshold` 控制低置信度框过滤。
- `nms_threshold` 控制重叠框抑制强度。
- `max_detections` 限制最大输出框数量，避免异常输入导致后处理耗时过大。
- `tracking` 模块用于检测框稳定，减少实时演示中的闪烁。

推荐使用 direct 模式：

```bash
scripts/demo/start_live_web_demo.sh --mode real --transport direct
```

启动后浏览器打开：

```text
http://localhost:8080
```

查看运行状态：

```bash
scripts/demo/status_live_web_demo.sh
```

停止演示：

```bash
scripts/demo/stop_live_web_demo.sh
```

### 8.3 调整 Web 图像质量和帧率

默认配置为每帧上传图像：

```bash
LIVE_IMAGE_QUALITY=88
LIVE_IMAGE_INTERVAL=1
```

如果需要降低带宽占用：

```bash
LIVE_IMAGE_QUALITY=80 LIVE_IMAGE_INTERVAL=3 \
scripts/demo/start_live_web_demo.sh --mode real --transport direct
```

如果只想观察远处区域，可启用图像 ROI 上传：

```bash
LIVE_IMAGE_ROI_ENABLE=true \
LIVE_IMAGE_ROI_NORMALIZED_XYWH='[0.25, 0.00, 0.50, 0.60]' \
scripts/demo/start_live_web_demo.sh --mode real --transport direct
```

说明：

- ROI 仅用于上传和观察图像区域，不一定改变检测区域。
- 检测 ROI 需要在 `preprocess.roi` 中单独配置。
- 当前现场主需求是调焦，建议先用全画面 `1:1` 或 `2x` 观察远处边缘。

1. 确认板端可 SSH：

```bash
ssh root@192.168.137.226
```

2. 确认相机连接在 `eth1`。
3. 确认 PC/WSL 与板端在 `192.168.137.0/24` 网段。
4. 确认模型文件存在：

```bash
ssh root@192.168.137.226 "ls -lh /opt/rk_app_current/artifacts/models/*.rknn"
```

### 10.2 启动演示

```bash
scripts/demo/start_live_web_demo.sh --mode real --transport direct
```

浏览器打开：

```text
http://localhost:8080
```

页面显示：

- `results`：收到的检测结果数
- `images`：收到的图像数
- `result fps`：检测结果帧率
- `image fps`：图像帧率
- `rx MiB`：累计接收数据量
- `idle s`：距离最近一帧的空闲时间

正常状态示例：

```text
result fps: 19.2
image fps: 19.2
results == images
idle s 接近 0
```

### 10.3 手动调焦说明

当前工业相机镜头需要手动调焦。如果画面表现为“近处清晰、远处模糊”，说明焦平面落在近处，属于光学对焦问题。软件侧无法恢复已经失焦的远处细节。

调焦建议：

1. 打开 Web 页面。
2. 切换到 `1:1` 或 `2x` 显示。
3. 对准远处目标边缘，缓慢旋转镜头焦环。
4. 以远处边缘最锐利为准。
5. 调焦完成后再进行检测演示或截图留档。

## 11. 常见问题

### 11.1 能 SSH 到板子，但 Web 没画面

检查状态：

```bash
scripts/demo/status_live_web_demo.sh
```

重点看：

- 本地 `9000` 和 `8080` 是否监听
- 板端是否有 `detect_cli` 进程
- `idle_s` 是否持续增大
- 板端日志是否显示 GigE source 打不开

### 11.2 result fps 高，但 image fps 低

通常是 `image_interval` 大于 1。当前默认已经改为：

```yaml
image_interval: 1
```

如果为了降低带宽改为 3，则图像帧率约为结果帧率的三分之一。

### 11.3 画面清晰但远处检测不到

可能原因：

- 目标在 416 输入下过小。
- 置信度阈值偏高。
- 远处区域占整图比例过小。

可尝试：

- 调整相机视场或位置。
- 使用检测 ROI，让远处区域占满 416 输入。
- 将 `conf_threshold` 从 `0.40` 试降到 `0.30`，同时观察误检。

### 11.4 远处画面模糊

这是手动调焦问题。先调焦，不建议用算法锐化作为主要方案。

### 11.5 640 模型为什么不用

历史 640 RKNN 产物容易触发 RKNN Transpose CPU fallback，输出规模较大，实时性不稳定。当前生产链路采用 416 INT8 模型，以保证 NPU 运行稳定和端到端实时性。

2. 跑一次关闭图像上传的纯检测验收，补强 `<=45 ms` 端到端检测指标。
3. 使用 `detect_coco80_rknn.yaml` 跑一次 COCO80 smoke test，补齐“>10 类”指标证据。
4. 若后续追求更高端到端帧率，可将 JPEG 编码和 TCP 输出彻底异步化，推理线程只保留最新帧结果。
5. 若需要提高远距离小目标检测效果，可考虑检测 ROI、滑窗 tile 推理或重新训练更适合远距离场景的数据集。
